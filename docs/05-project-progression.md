# 05 - Project Progression

## Purpose
Projects prove that learned skills can be combined into working software. They use the same workspace and evaluator infrastructure as normal challenges, but with broader requirements and less scaffolding.

## Suggested progression
1. **Counter** - state, functions, button events
2. **Tip Calculator** - input, numbers, validation, output
3. **Quiz** - arrays, objects, state transitions, scoring
4. **Todo List** - collections, IDs, add/remove/update, rendering
5. **Form Validator** - conditions, strings, user feedback
6. **Memory Game** - state machines, arrays, events, timing
7. **Search UI** - filtering, derived state, empty states
8. **API Dashboard** - async requests, loading/error states, data rendering
9. **Local Notes App** - persistence and basic application structure
10. **Small Full App** - multi-feature composition with reduced guidance

## Project structure
A project is a content package with ordered or partially ordered milestones:
- setup state
- implement behavior
- render output
- handle edge cases
- refactor
- optional stretch goal

## Guidance shift
Early projects expose one milestone at a time. Later projects show a feature brief and tests, allowing the learner to choose implementation order.

## Completion criteria
Project completion should require functional checks, not exact source matching. Bonus awards may recognize clean completion, edge-case handling, or low-hint completion, but should not penalize experimentation.
