# UX Principles

## 1. One obvious next action
At any moment, the interface should make the next useful action visually obvious.

## 2. Progressive disclosure by default
Do not expose tools, panels, tabs, diagnostics, or metadata until they are useful to the current task.

## 3. Workspace over dashboard
When a user is solving, the workspace is the product. Navigation, progress, rewards, and account features must recede.

## 4. Feedback without punishment
Use `Complete`, `Not there yet`, and contextual diagnostics. Avoid failure-heavy language, red walls, and score loss for experimentation.

## 5. Teach through the code
Prefer highlighting, inline explanations, runtime state, and targeted HUD messages over long prose.

## 6. Same surfaces, different teaching policy
Learn, Projects, and Interview reuse the same editor, runner, workspace, HUD framework, and progress engine.

## 7. Preserve flow
Assistant messages should appear only on meaningful events: pause, parseable line, misconception, repeated issue, partial goal, or completion.

## 8. Syntax color is core infrastructure
Correct language-aware tokenization, diagnostics, and semantic styling are required from the first release.

## 9. Reward progress in small meaningful units
Give visible acknowledgement for real milestones, but avoid constant confetti or meaningless badges.

## 10. Density follows skill
Beginners get a minimal surface. Advanced and interview users may opt into more test/debug detail.
