# 14 - Game Economy & Awards

## Goals
Make progress visible and satisfying without incentivizing shallow repetition or punishing mistakes.

## Core systems
### XP
General progression earned through meaningful completion.

### Levels
Presentation layer over cumulative XP; no critical curriculum should be permanently locked behind grinding.

### Streaks
Optional consistency signal. Missing a day should not destroy long-term progress.

### Awards
Milestones representing real accomplishments.

### Mastery
Separate from XP; reflects skill competence rather than activity volume.

## Example challenge rewards
- complete challenge: +20 XP
- optional first-pass bonus: +5 XP
- optional low-hint achievement: +10 XP
- stretch objective: +10 XP

Never subtract XP for failed attempts.

Partial evaluator progress earns concise acknowledgement but not repeatable XP. Reward grants are idempotent and attach to meaningful challenge or lesson completion.

## Example awards
- **First Program** - complete the first executable challenge
- **Bug Hunter** - repair 25 intentionally broken programs
- **No Hint Needed** - complete a meaningful set without assistant hints
- **Array Master** - reach the target array mastery level
- **Two Pointer** - finish the introductory two-pointer sequence
- **Ship It** - complete the first project

## Anti-grind rules
- reduced/no mastery gain for repeating trivial solved content
- cap exploitable XP loops
- awards based on distinct accomplishments
- mastery requires diverse evidence

## UI principle
Game information should be visible but secondary to coding. The editor must remain the dominant surface.
